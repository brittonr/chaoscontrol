## Context

ChaosControl already has an assertion-readiness promotion gate that fails closed when gap counts or anti-claim text are weakened. The remaining assertion-readiness work is now practical remediation: finding exactly which accepted-proof assertions are unhit or non-passing without digging through raw JSON.

## Goals / Non-Goals

**Goals:**
- Render deterministic gap details derived from committed accepted-proof `assertions.json` artifacts.
- Include stable assertion ID/message/kind/category/verdict/hit count fields where present.
- Keep the report cheap and static; no KVM campaign or fresh dogfood run is required.

**Non-Goals:**
- Do not reclassify current accepted evidence or change replay proof status.
- Do not claim workloads are promotion-ready merely because details are easier to inspect.
- Do not mutate raw dogfood evidence.

## Decisions

### 1. Add Markdown details below promotion guidance

**Choice:** Add a `## Gap details` section to `docs/assertion-readiness-status.md` generated by `chaoscontrol-evidence`.

**Rationale:** The status document is already the operator entrypoint for assertion-readiness gaps and is checked for freshness.

**Alternative:** Add a separate JSON report. Rejected for this slice because the immediate need is operator triage and the existing status report already binds accepted proofs to committed artifacts.

**Implementation:** Extend the pure row-building logic to collect detail records while preserving the existing summary/count parser and promotion gate behavior.

## Risks / Trade-offs

**Large report growth** → Bound details to gap classes only (`unhit`, `non-passing`) and use one compact bullet per assertion.

**Overclaiming** → Keep existing summary, promotion guidance, and anti-claim text unchanged.
