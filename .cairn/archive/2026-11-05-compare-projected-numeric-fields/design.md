## Context

The upstream map/filter example computes a numeric field and filters it. Local projections and running counts are stored in derived strings. Field lookup already defines canonical kind/text/process/source_kind precedence over same-named projections; numeric comparison already implements six finite binary64 relations with explicit missing-value behavior.

## Decision

Add EventPredicate::FieldNumber { field: String, comparison: NumberComparison, value: serde_json::Number }. Validate the field with the existing nonempty/control-free/256-byte contract and validate finite threshold conversion exactly like JsonNumber, even on empty input or in skipped compound branches. Reuse field_value and NumberComparison::matches without changing exported comparison APIs, existing predicates, schemas or source identity. Upgraded readers are required for the new variant.

Parse the complete selected field using serde_json::from_str::<serde_json::Number>, accepting standard JSON decimal/exponent forms and JSON whitespace. Convert only the parsed Number into an inline Value for the existing comparison; do not clone the input string or parse a surrounding object. Missing fields, empty/malformed strings, quoted JSON strings, booleans, null, arrays/objects and overflow/nonfinite representations are nonmatches rather than parser errors. Signed zero, rounding beyond 2^53 and underflow follow existing finite binary64/serde_json semantics. This is not JavaScript Number() coercion: leading +, hexadecimal, leading-zero integers, empty text and Infinity/NaN are not admitted numbers. NotEqual requires a numeric value; Not(Equal) also selects missing/nonnumeric values. Canonical text that is not JSON remains admissible when another field is selected; JsonTextNumber's visited-parse errors are unchanged.

No new operation, cache, parse-error variant or source mutation. The enclosing Filter/RunningCount supplies existing row charges; compound child visits use existing charges, short-circuiting and shared node/depth accounting. Parsing is bounded by admitted canonical text/derived byte limits (8 KiB/64 KiB aggregate), not a new per-field cap. Existing source admission, canonical ordering/deduplication, result caps, moments and complete expression/source/result receipt checks remain unchanged.
