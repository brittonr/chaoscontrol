# Repeatability cause and fix

Date: 2026-11-05. Guest cohort from this worktree:

- kernel: `/nix/store/5aya7zvynanjw5mh3xvz40sga3zfsmn8-chaoscontrol-vmlinux/vmlinux` (`.#kcov-vmlinux`)
- initrd: `/nix/store/ymfxhvyv4zr3la0q4k6h6famb9avz8y9-chaoscontrol-initrd-raft` (`.#initrd-raft`)

## First divergence

The gate reproduced a mismatch with the previous build:
`Mismatch { round: 1, branch: Some(0), reason: BranchDigest }` for the control
profile with zero operational rounds.

Per-branch component diagnosis on two fresh `1 round × 1 branch × 200 ticks`
runs showed:

| Component | Run A | Run B |
| --- | --- | --- |
| ticks | 1372 | 1373 |
| exits | 137200 | 137300 |
| coverage bits | 6221 | 4688 |
| oracle digest | differed | differed |
| halted digest | equal | equal |

The branch records exactly 100 exits per tick, so the runs differed by one
bootstrap tick before exploration started: `run_until_setup_complete` observed
`setup_complete` at tick 1172 and 1173. Guest boot progress was host-dependent.

## Cause

Explorer controllers used `VmConfig::default()` with `cpu.hide_tsc = false`.
The guest kernel therefore used TSC-based timekeeping/calibration during boot,
and host timing shifted the tick at which setup completed. Every later branch
inherited the shifted tick/exit origin, changing coverage and oracle facts.

## Fix

`Explorer::simulation_config` now hides the TSC for explorer-owned controllers
(`vm_config.cpu.hide_tsc = true`), matching the admitted guest determinism
boundary. Regression: `explorer_controllers_hide_tsc_for_deterministic_boot`.

## Verification

Fresh-process gate receipts after the fix:

| Profile | Result |
| --- | --- |
| control, 1 round × 1 branch × 200 ticks, run 1 | `Match` |
| same, run 2 | `Match` |
| same, run 3 | `Match` |
| control, 3 rounds × 4 branches × 1000 ticks | `Match` |
| `premature_commit`, 3 rounds × 4 branches × 1000 ticks | `Match` |

Each gate compares two separate explorer processes and excludes nothing: both
runs recorded zero operational and zero unavailable rounds.

## Boundaries

This supports seed repeatability only for the recorded kernel, initrd, seed,
host, and configuration. It does not prove determinism for other hosts, SMP
profiles, or workloads. The earlier gate mismatch and its component diagnosis
remain retained above; the fix changes no assertion, replay, or fault semantics.
