# Counterfactual Replay Witness Design

## Context and observed foundation

This is a spec-only, active native change. The immediate outcome is one inspectable, retained adjacent replay pair; the lasting capability is independently checkable, bounded evidence about one declared intervention. The first consumer is the local Rust-workload operator already using explorer minimize/reproduce. Replay/evidence maintainers own the contract and its maintenance; explorer maintainers own candidate generation. All behavior below is planned unless explicitly identified as source-observed.

## Decisions

### Decision: One omitted scheduled fault is the declared intervention

Begin with an admitted v2 failing bug, its retained replay parent, the existing fault schedule, and optional existing-minimizer output as a candidate schedule. Independently confirm the selected starting schedule against that parent. Search single-entry omissions from a confirmed failing schedule in ascending original canonical entry index. Same-time entries retain original order and occurrence identity. A minimal schedule is neither needed nor claimed. Empty resulting schedules are allowed when omitting the sole entry; an empty starting schedule yields no candidate. A pair with no qualifying neighbor is a valid bounded search result, not a successful witness.

Record a versioned intervention descriptor containing the full before/after schedule identities, original entry index and canonical entry bytes, omission kind, branch schedule index mapping, and the exact round boundary before the changed entry could first be selected. All other scheduled entries and their timing/parameters/labels/order must remain equal. No randomized extra fault generation, seed/config/topology change, or memory/register edit is admitted. Controls unavailable at an exact supported boundary return `unsupported_control`; they never trigger timer-based or weaker replay. The common parent must precede the intervention; pending effects already encoded in the parent remain unchanged.

Schedule rebinding intentionally changes schedule/run/attempt identities. Each run validates these identities against its own schedule and ledger. Cross-run prefix comparison uses an explicit, validated correspondence from each retained original entry to its branch-local index and run envelope; it does not demand identical schedule hashes and does not silently erase fault timing, outcomes, state, order, progress, payload, or execution observations. An unexplained difference before the declared intervention invalidates pairing. If the existing clean-run transition changes other execution-relevant state, reject that candidate until the replay owner can prove preservation; do not waive the one-intervention rule.

### Decision: Bind a complete local witness envelope

The planned manifest schema is `chaoscontrol.counterfactual-replay-witness.v1`. It binds:

- Source/build identity; exact kernel/initrd/disk/guest binary content identities; complete deterministic configuration identity, seed, VM/vCPU topology, progress mode/capability profile and complete catalog identities.
- Selected exact v2 assertion descriptor, canonical descriptor bytes, fingerprint, catalog token and compatibility alias if any; the alias and dedup key are never authority.
- Existing retained common-parent snapshot ref, depth, tick, codec/schema/digest and restore validation result; parent snapshot and prefix trace refs remain loadable from the local artifact root.
- Declared intervention and boundary identity; common-prefix start/end, trace identities and exact comparison result; finite configured budgets and deterministic candidate order/progress.
- Per-run schedule and run identities, recording and canonical trace refs/digests, branch-local oracle observation/verdict refs, attained horizon, completion state and exact-replay verification result.
- First-divergence descriptor and links, or an explicit absent/incomplete divergence classification; content-bound pair identity, outcome, diagnostic reason, and non-claims.

Use existing artifact digest algorithms for existing envelopes; a versioned domain-separated BLAKE3 identity binds new canonical witness metadata. Local paths must be relative, contained within the artifact root and digest-checked on reopen. A partial write cannot publish a complete pair: write/verify required artifacts first, then atomically publish the complete manifest. Failed writes retain only a labelled partial receipt if possible. Reopen verifies bytes, not only their presence. A witness manifest explicitly retains parent/checkpoint refs and oracle outcome artifacts; it must not serialize the current `Recording` and assume serde-skipped fields survived.

### Decision: Positive branch-local outcomes and a predeclared horizon

Before any candidate runs, declare the common comparison horizon as `comparison_ticks_after_parent`, using each branch's own completed simulation ticks from the common parent. It is an observation budget, not a statement that equal post-divergence tick numbers perform equal work. Use checked arithmetic. Both sides must complete the horizon without operational failure; the failing side must evaluate and fail the selected target in that interval; the other side must positively evaluate the same target and finish without its violation according to the existing kind-specific oracle semantics. A target failure may be recorded before the horizon, but a run stopped there is not a complete paired comparison.

Keep parent counters as historical evidence; obtain branch-local target events/counts by an admitted clean branch observation interval or validated before/after accounting, never by treating restored cumulative verdicts as fresh evaluation. `Unexercised`, inherited-only hits, unrelated failures, no bug file, and a Boolean `!Failed` cannot qualify a non-failing side. Because current `Unreachable` records cannot demonstrate its non-hit condition was actually evaluated, such a target is `unsupported_target_observation` unless a positive evaluation channel already exists and is admitted; do not change assertion semantics to manufacture proof. Sometimes/reachability kinds use their existing rules plus positive branch-local evaluation and completed horizon; unsupported interpretations are explicit, not inferred.

Missing/corrupt inputs reject admission. Watchdog/timeout, early exit, missing/truncated trace, poison, unsupported control, or runtime resource exhaustion are indeterminate. Search-wide budget exhaustion is partial. No status becomes non-failing because it lacks a failure record.

### Decision: Validate each run, then compare only the shared prefix

Retain new canonical round, exact SMP transition, and fault-stage traces during each candidate's own run. Validate shape, identities, bounds, round completeness, ledger transitions and checkpoint association independently. Then replay each retained branch from the common parent against that branch's own recording through its horizon. Never compare an intentionally changed suffix against the original failing recording. The missing counterfactual event/trace capture in today's API is implementation work, not assumed solved by reusing `ReplayResult`.

The trace comparison contract orders completed rounds by branch-local tick; within each round use an explicit versioned phase sequence: fault-stage observations in ledger order, pure-core canonical events in event order, then exact SMP traces by VM index and transition index. This is a comparison serialization order, not a claim that it merges all hardware events chronologically. Validate each source's native order before constructing it. The manifest records this ordering version. Compare all pre-intervention entries and boundary state using validated entry/run correspondence only. A boundary at the parent has an explicitly empty execution prefix and requires equal admitted restored state; it must not claim earlier execution was reverified.

After the boundary, locate the earliest unequal canonical comparison entry from the shared prefix, retaining the last equal entry, each side's first unmatched entry (including insertion/end-of-stream), event kind/field, local tick, VM/vCPU where supplied, transition index, artifact digest/ref and exact event values or bounded references. Call it the first divergence in the retained canonical ordering, not the first differing machine instruction or inferred source cause. Once entries differ, remaining suffixes are independent; no tick-based realignment or equivalence is inferred. Changed schedule-derived identity fields alone are intervention metadata, not execution divergence. Without a complete comparable suffix or a demonstrable canonical divergence, retain an incomplete result and do not publish a complete witness.

### Decision: Named finite limits and deterministic selection

Admit the following explicit positive finite configuration values, subject to existing hard caps and checked arithmetic: `max_candidate_schedules`, `max_run_evaluations` (including baseline confirmation and per-side verification replays), `comparison_ticks_after_parent`, `max_trace_records_per_run`, `max_trace_bytes_per_run`, `max_artifact_bytes_total`, `max_snapshot_bytes`, `max_manifest_bytes`, and `run_watchdog_timeout_ms`. Do not invent default benchmark counts or performance targets. Configuration admission must prove the capacity needed for one baseline and one candidate plus both verification replays fits the selected budget, or reject before executing. Runtime admission reserves required trace/artifact capacity before each evaluation where possible; exceeding a cap never silently truncates accepted evidence.

Candidate order is ascending original schedule entry index, independent of host completion order. Run one candidate at a time using the same restored parent. Baseline confirmation, candidate execution and independent verification are counted explicitly. Return the first qualifying pair, with exact attempted/exhausted counts and stopping reason, not a ranked list or globally best pair. An indeterminate candidate is recorded and the next candidate may run only if admitted limits permit; no hidden retries. If all candidates are determinately examined without a pair, return `no_pair_found`; if any candidate is indeterminate, the bounded conclusion remains incomplete. Budget exhaustion stops partial and names the exhausted bound.

### Decision: Pure evidence core, local effect shell, explicit operator adoption

Extend existing `chaoscontrol-replay-evidence-core` with witness DTOs, canonical identity/binding admission, finite-limit accounting, candidate order, target-outcome classification, correspondence/prefix/divergence comparison and publication eligibility. Reuse pure simulation/scheduler/fault validators in their current owners. The core consumes supplied observations and artifact identities and has no filesystem, process, KVM, clock or network effects. `chaoscontrol-replay` executes/restores/records/verifies branch runs; explorer owns existing-minimizer integration/candidate enumeration; `chaoscontrol-evidence` owns validation/report projections. Existing snapshot-store contracts remain the input; no new store, codec, digest migration or new crate is needed.

The planned local CLI extension is `chaoscontrol-explore witness --bug <bug.json> --config <witness-config> --output <root>` with an exact identity selector in the admitted config. Planned offline inspection is `chaoscontrol-explore witness-show --manifest <witness.json>`, and verification is `chaoscontrol-explore witness-verify --manifest <witness.json>`. These are proposed interfaces, not existing commands. The report prints digest-bound links to failing/non-failing recordings, branch verdicts, common parent, exact target descriptor, intervention, common-prefix endpoint and first divergence; it prints runnable verify/show commands and the retained replay inputs needed for rerun. No GUI is introduced. Missing artifacts produce named errors, not broken success links. Existing minimize/reproduce commands remain valid and do not silently emit stronger evidence.

The witness outcome is an additional bounded comparison claim. Each branch preserves its original replay verdict artifact/class. Only an independently eligible failing replay may carry `snapshot_backed_reproduced`; `snapshot_backed_not_reproduced`, schedule-only gaps, dry-runs or a lifecycle PASS cannot establish a complete witness. Positive non-failing qualification is a separate witness predicate, not a reinterpretation of existing replay class or exit status.

## Dependencies and overlap

- Current exact replay plus retained parent snapshots and admitted v2 catalogs are the actual inputs. Missing inputs require fresh retained runs, not reconstructed historical traces.
- `repair-incremental-snapshot-lineage` alone owns overlay correctness. Invalid or unverified deep cohorts block evidence; this package does not repair them or change parent lineage.
- `causality-analysis-engine` may consume witnesses for attribution/interleaving minimization; `extract-failure-reducer-core` owns generic reducer extraction; neither is needed for bounded single-entry pairing.
- `externalize-large-dogfood-artifacts` owns remote/storage-neutral materialization. This package stays local. `add-persisted-debugger-replay` may later share recording persistence and move the existing snapshot store intact; this package does not depend on that unimplemented migration or own it. Page-addressed evaluation and PMU evidence are independent.

## Verification and risks / trade-offs

Implementation acceptance requires focused positive/negative pure fixtures for identity changes, one-vs-multiple schedule deltas, same-time indices, catalog collisions, inherited target hits, horizon overflow, event insertion/truncation, and schedule-ID correspondence. Include non-monotonic fault outcomes to demonstrate that one successful pair implies neither monotonicity nor global minimality. Local KVM smoke must run a controlled Rust workload with a known admitted target and retained parent, produce both horizon-complete outcomes, independently replay both sides, reopen the manifest and exercise CLI/report links. A separate negative smoke must force bounded timeout/unsupported control or trace exhaustion and observe indeterminate/partial output without a complete pair. Record exact config, source/build/guest hashes, seed, commands and artifact refs.

Trace retention and extra verification replay cost are explicit and bounded, not performance promises. Aggregated assertion state and schedule-derived identity changes are correctness risks addressed by branch-local outcomes and explicit correspondence. Supported fault controls may produce no qualifying pair. A first canonical divergence is an inspectable observation, not an inferred source location or unique cause. No product fixtures, KVM campaigns, measurements, runtime implementation, sync/archive or release closeout have run in this planning change. Structural proposal/design/tasks gates only establish lifecycle artifact facts.
