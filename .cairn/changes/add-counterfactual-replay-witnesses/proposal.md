# Add Counterfactual Replay Witnesses

## Why

The immediate outcome is an operator-readable, retained failing/non-failing replay pair for one exact assertion, one verified common prefix, and one declared fault-schedule intervention. The durable capability is bounded counterfactual evidence that can be reopened and checked without trusting a minimizer's Boolean result or raw logs. The concrete first consumer is the local operator running `chaoscontrol-explore minimize` and `reproduce` on an admitted v2 bug; the replay/evidence maintainers own admission, CLI compatibility, and evidence wording, with explorer maintainers owning candidate enumeration.

Source review at `06ac3cdb05c22e25600a583c43125e434b5f35b0` shows that [`Minimizer::triggers_bug`](../../../crates/chaoscontrol-explore/src/minimizer.rs#L273-L349) restores a parent and resolves an exact assertion but returns only whether the verdict is `Failed`. This does not establish that a different candidate positively reached its horizon and evaluated the target. [`ReplayEngine::replay_with_schedule`](../../../crates/chaoscontrol-replay/src/replay.rs#L309-L380) supports a modified schedule, but does not collect counterfactual events or enforce its target horizon. These are integration starting points, not existing witness guarantees.

The design reference is [RewindVM at immutable revision 6ec1f68de82ae3e657cdfcbe0d83f349bb367082](https://github.com/fzakaria/rewindvm/tree/6ec1f68de82ae3e657cdfcbe0d83f349bb367082), specifically [`check.rs`](https://github.com/fzakaria/rewindvm/blob/6ec1f68de82ae3e657cdfcbe0d83f349bb367082/crates/rewind-core/src/check.rs). Its window narrowing documents edge-minimality, non-monotonic outcomes, and retaining the run one step shorter. ChaosControl adapts the adjacent-run evidence idea, not its algorithm or its scheduler. The reference is neither a runtime dependency nor parity proof. Its engine is MIT, guest kernel patch GPL-2.0, and desktop app proprietary; this work imports no desktop app code or external runtime dependency.

## What Changes

- Admit a hash-bound witness manifest tying two independently validated runs to the same guest artifacts, deterministic configuration, seed, topology, complete admitted catalog, retained common parent snapshot, selected v2 assertion identity, horizon, boundary, and exactly one schedule-entry omission. Reject unrelated differences. r[chaoscontrol.replay_witness.pair_binding]
- Reuse existing minimizer schedule ordering and replay/controller fault-run APIs to search for one qualifying adjacent pair, not a generic reducer. Require positive failing evidence and positive horizon-complete, target-evaluated non-failing evidence from branch-local observations. r[chaoscontrol.replay_witness.outcomes]
- Validate each run against its own retained traces before comparing the exact pre-intervention execution prefix. Retain the earliest canonical divergence with branch-local locations and actionable local CLI/report links. r[chaoscontrol.replay_witness.trace_comparison] r[chaoscontrol.replay_witness.operator_surface]
- Admit explicit finite candidate/evaluation/trace/artifact and per-run tick/time limits, deterministic candidate order, and partial/indeterminate results rather than fabricated pairs. r[chaoscontrol.replay_witness.bounded_search]
- Keep pure identity, admission, ordering, comparison, and classification separate from KVM, artifact I/O, and rendering. Preserve existing replay evidence classes and accepted verdict meaning. r[chaoscontrol.replay_witness.ownership] r[chaoscontrol.replay_witness.evidence_boundary]

## Impact

- **Planned implementation surfaces:** `chaoscontrol-explore` minimizer/corpus/CLI; `chaoscontrol-replay` recording, replay, and branch trace retention; pure schedule/trace validation in `chaoscontrol-sim-core`; witness admission and operator report integration in `chaoscontrol-evidence`. This change itself only authors this native proposal, design, delta specification, and linked task list; metadata remains native and untouched.
- **Adoption:** opt-in witness creation after an admitted v2 snapshot-backed failing replay, accepting the existing minimizer's schedule as an optional starting candidate. Existing minimize/reproduce invocations retain their behavior; consumers explicitly request and verify witness artifacts. Historical ID-only bugs remain diagnostic-only.
- **Acceptance:** a known controlled Rust workload must retain a one-entry-difference pair, independently replay each side, show the exact common prefix and first divergence, and resolve every report link. Negative verification must reject target/catalog/guest/config/parent changes, inherited-only target hits, absent or forged traces, early stop, timeout, unsupported controls, and exhausted budgets. Future focused fixtures and local KVM smoke are required but have not run in this spec-only change.
- **Failure behavior:** invalid bindings reject before mutation; operational or unsupported execution is indeterminate; finite search/retention exhaustion yields a partial receipt and no complete witness claim. No weaker determinism fallback is allowed.
- **Dependencies and overlap:** existing exact replay and retained snapshot storage suffice. `repair-incremental-snapshot-lineage` owns overlay correctness; faulty or unverified deep cohorts block witness evidence rather than being silently repaired here. `causality-analysis-engine` owns general attribution/interleaving minimization; `extract-failure-reducer-core` owns reusable reduction; `externalize-large-dogfood-artifacts` owns remote/storage-neutral materialization. They may consume witnesses but are not prerequisites. The new debugger, page-store evaluation, and PMU-evidence proposals are not hard dependencies.
- **Evidence limits:** observed source behavior only; no retained qualifying pair, performance measurement, product fixture, KVM smoke, implementation approval, synchronization, archive, or release claim exists. Structural lifecycle gates cannot supply any of those proofs.

## Out of Scope

No globally minimal schedule, monotonicity assumption, unique-cause claim, ranked attribution, generic reducer extraction, arbitrary memory/register edits in an accepted witness, inferred source location, GUI, containers, hosted services, non-Rust guest support, new snapshot store, altered replay verdict semantics, or general program-correctness proof. The scope is Rust-only, local-machine execution and bounded evidence.
