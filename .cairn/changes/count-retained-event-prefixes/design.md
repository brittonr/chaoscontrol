## Context

The upstream fold example counts severity-20 events along a timeline, attaches the running total to every event, then selects severity-30 events. Local retained envelopes have integer ticks and source positions rather than admitted multiverse lineage. Their supplied order may be arbitrary and duplicate source positions retain the first projection.

## Decision

Add EventQuery::RunningCount { input: Box<EventQuery>, predicate: EventPredicate, field: String }. Reuse predicate admission, regex cache, short-circuit semantics, nested logical-work charges and Filter's predicate-root node/depth accounting; validate field names before any row evaluation, even on empty inputs. Propagate the input's moment. Query/receipt schemas and older semantics stay unchanged; new readers are required for the variant.

Evaluate the child and charge one logical operation per materialized candidate, including duplicates, before aggregation. Admit every child row before deduplication so invalid hidden projections cannot be discarded. Stable-sort in place by existing event_order only when needed; deduplicate source positions using the same stable first-wins rule as final evaluation. In canonical order, evaluate the predicate on each original row before overwriting the requested derived key. Increment a checked u64 counter on matches and annotate all unique rows with its decimal value, inclusive of the current row, otherwise retaining the current total. Start at zero; All([]) counts all positions, Any([]) counts none. At equal ticks, source ID then source sequence resolves order; there is no simultaneity or per-source reset. Earlier child filters restrict what is counted, while downstream filters only select annotated observations.

Reuse an existing target key/value allocation when overwriting where possible; insert an owned field name only for new entries. No extra event vectors or per-prefix sets; sorting and deduplication reuse the child vector. Admit every generated row immediately, enforcing derived capacity/bytes even when an outer filter/narrow would hide the annotation. Predicate errors and all bounds fail the whole evaluation before CLI publication. Existing final canonical ordering, prefix truncation, row bytes, complete-expression and canonical-source receipt binding remain effective. Sorting work has the existing bounded-input model, not a CPU/RSS/deadline guarantee.

## Verification

Capture replay baseline, inspect enum references and admit native lifecycle gates before implementation. Reproduce unknown RunningCount with a consumer regression. Verify prefix totals against an independent prefix oracle over source permutations, zero/max/tied ticks and multiple sources; empty/all/none predicates; duplicate first-projection precedence; predicate-before-overwrite; projected/regex/compound predicates and downstream selection; intermediate/output admission; field/regex/pointer admission on empty input; visited versus skipped JSON errors; shared logical/structural/scan/result bounds and truncation; moments and query/source/result receipt drift. Exercise actual CLI positive/negative paths with full row comparisons and no partial failure artifacts, then run replay tests, Clippy, workspace compilation, formatting, scope/evidence checks and scoped gates. Synchronize the requirement while keeping the change active. Preserve/exclude the user's confined-pointer test.
