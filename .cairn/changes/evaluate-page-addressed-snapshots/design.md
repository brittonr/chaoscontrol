# Design: Evaluate Page-Addressed Snapshots

## Context and Source Foundation

This is a finite evaluation plan, not authorization to migrate production storage. The reviewed ChaosControl source revision is `06ac3cdb05c22e25600a583c43125e434b5f35b0`.

- `crates/chaoscontrol-vmm/src/snapshot.rs:24-269`: memory is `Full(Vec<u8>)` or an `Arc<Vec<u8>>` base plus a sorted page map. Overlay serialization copies the full base and each dirty page; in-memory sharing is not persistent page dedup. The existing 4096-byte granularity motivates the experiment, not a performance claim.
- `snapshot.rs:278-410,688-779,915-961`: completeness metadata binds schema `2`, profile `exact-x86-kvm-v1`, topology, and inventory. CPU/KVM, scheduler/progress/HLT, virtual clock, entropy, faults, serial, coverage and virtio transport/backend state must survive, not just memory.
- `crates/chaoscontrol-vmm/src/controller.rs:2540-2564`: the simulation envelope additionally owns per-VM status, network fabric, global tick/fault engine, stalls, clock effects, process attempts, pending observations and operation sequence. Page storage must not omit these.
- `crates/chaoscontrol-explore/src/snapshot_store.rs:19-194,201-374`: the baseline stores a whole CBOR+zstd envelope with compressed-byte SHA-256, bounded reads/decompression, shape/metadata checks, temp-write/rename publication, and keep-list GC. The optional host redb seam is not the redb guest workload. Observe this baseline as it is; do not infer durability or race safety from rename alone. A separately reviewed ownership-only move of this implementation into `chaoscontrol-replay` would not change this evaluation's codec/reference baseline or become a prerequisite.
- `.cairn/changes/repair-incremental-snapshot-lineage/` records missing inherited/host-written pages and sibling revert gaps, with depth-three-and-higher replay failures. Its implementation tasks remain uncompleted in the reviewed plan. Deep cohorts cannot be assumed valid.
- `.cairn/changes/externalize-large-dogfood-artifacts/` owns storage-neutral materialization, retention migration and adapter bounds. This experiment must preserve those identity/evidence boundaries.
- `docs/replay-proof-coverage.md` names `dogfood-results/raft-fresh-v2-proof-20260809/` and `dogfood-results/redb-fresh-v2-proof-20260809/` as candidate admitted cohorts. Their documentation status is a lead, not a substitute for fresh artifact admission under the exact evaluation profile.

## Decisions

### 1. Compare three explicitly different cost surfaces

The evaluation maintainer registers a finite manifest before execution. It names (A) current Arc-overlay capture/clone/materialization/restore in memory, (B) current complete CBOR+zstd retained artifacts, and (C) an isolated persistent 4 KiB BLAKE3 page store plus keyframe DAG. A and B are complementary baselines, not interchangeable denominators. Compare A's memory/capture costs and B's persistence costs with corresponding C stages, retaining complete end-to-end totals. Use the same logically complete states, fixed guest actions, seed, configuration, snapshot positions, and continuation targets. Baseline source and codec versions, compression settings and build identities are explicit. No SHA-256-to-BLAKE3 conversion of existing references occurs.

C has its own experimental schema/domain and scratch root; production snapshot consumers continue using existing references. A keyframe contains ordered VM memory geometry, parent identity or a complete root, local page replacements and all non-memory simulation/VM state. A deterministic logical-time interval selects keyframes; upstream wall-time-adaptive placement is deliberately not adopted. A seek selects the greatest admitted keyframe not after the target, materializes it, then runs the bounded exact continuation; unsupported targets fail, never approximate. Cross-VM identical content may deduplicate physically, but VM/page identities and topology remain distinct in the keyframe.

### 2. Freeze bounded Nickel profiles before observing results

A Nickel contract will require finite positive budgets and reject overflow/inconsistent geometry before allocation or I/O. Profile fields are `max_cases`, `max_vms`, `max_guest_bytes_per_vm`, `max_snapshots`, `max_branches`, `max_lineage_depth`, `max_dag_nodes`, `max_page_objects`, `max_manifest_bytes`, `max_non_memory_bytes`, `max_compressed_page_bytes`, `max_store_bytes`, `max_staging_bytes`, `max_gc_scan_objects`, `max_continuation_ticks`, `max_continuation_instructions`, `max_seek_targets`, `repetitions`, and `host_operation_timeout_ms`. `keyframe_interval_ticks`, explicit `seek_targets`, seeds, case ordering, dense/sparse page sets, cache protocol, and compression settings are recorded. Budget values come from the admitted local machine/cohort and owner-reviewed protocol, not arbitrary benchmarks in this document. The experimental page size is a format invariant, 4096 bytes; partial-tail geometry is rejected rather than silently truncated.

The declared case table is finite, not an unbounded Cartesian campaign: sparse unique changes, dense unique changes, repeated identical and zero pages, unchanged inherited pages after parent restore, host-written restore pages without guest rewrites, a sibling after writes outside its parent, deep chains through the configured bound and one-over-bound rejection, multi-VM state with shared content and distinct identities, and non-memory-only state transitions. Include exact-budget and exhaustion cases. Include at least the Raft and redb retained candidates when admission succeeds; otherwise list each blocked cohort and why in a defer/reject receipt. No synthetic success silently replaces their missing evidence. Depths implicated by the lineage defect require independent validated admission; shallow evidence does not clear deep cases.

Case IDs, VM IDs, page indices, parent resolution, snapshot positions, seek targets, reachable-object traversal and failure selection have a canonical total order. Wall-clock deadlines are shell cancellation/diagnostic bounds only. Timing or timeout must never change guest instruction authority, virtual time, schedule, case content, or checkpoint positions; an interrupted row is incomplete rather than a valid deterministic alternative.

### 3. Fidelity admission precedes metric interpretation

At every measured capture point, capture an independent full snapshot as the oracle. Validate both the baseline overlay and C's complete materialization byte-for-byte per VM against full memory, and compare canonical full non-memory state with the full-snapshot oracle. Resolve identities/topology/inventory before any restore mutation; never normalize away state differences or use C to repair A/B. Comparing two broken incremental representations is not an oracle.

Restore A/B and C into independently initialized fresh controllers and compare them with the long-lived branch controller at the same point. Run the same bounded continuation under existing exact-progress authority, checking canonical schedule/round traces, final complete-state identities, assertions/outcomes and errors at declared boundaries. Cover sibling switching and deep ancestry, not just one snapshot. A mismatch, incomplete inventory, known unresolved lineage gap, missing retained object or failed continuation blocks that cohort's paired metrics and any adopt recommendation. Raw diagnostic timings may remain labeled invalid/not-comparable; they cannot feed savings/speedup aggregates. Route baseline repair to its existing owner.

### 4. Content addressing is bounded validation, not trust

Experimental page references bind an explicit schema/domain, BLAKE3 algorithm and digest, exact decoded length of 4096, encoded byte length/codec and safe local locator. Manifests bind exact bytes/digest, schema/profile, VM topology/geometry, complete-state identity and parent linkage. Bound bytes and counts before decoding/allocation; checked arithmetic precedes page-offset access. Reject duplicate/ambiguous VM or page entries, out-of-range offsets, incompatible parents, unsupported algorithms/codecs/schemas, invalid hash/length, dangling objects, truncated/oversized/decompression-bomb payloads and noncanonical order. Do not treat upstream's zero-page sentinel as a cryptographic digest: use an explicit versioned zero-page variant with exact zero materialization, or store the real BLAKE3 page object.

Resolve the complete parent closure with visited identities and a configured depth/node bound; cycles and one-over-depth fail before guest mutation. Reject absolute/traversal paths, symlink escapes and nonregular objects with root-confined reads. A page lookup is verified against bytes, not trusted index metadata. No missing page becomes zeros, no corrupt ancestor is skipped, and no wall-clock/timer scheduling fallback is admitted. A failed preflight yields a typed blocker; post-mutation execution failure follows existing controller poison rules and cannot publish a successful evaluation row.

### 5. Publish and collect only in an isolated pinned-root protocol

Pin the entire admitted root set before measurement: source cohorts, replay parents, explorer frontier/branches, active materializations/readers, evaluation manifests and decision/raw-observation artifacts. Published proof artifacts are read-only and never GC candidates. Experimental writes stage into the dedicated bounded scratch root, verify the complete page/ancestor/state closure, and publish a complete manifest last with an atomic visibility boundary. Record interrupted-write, hash failure, missing ancestor, publication failure and space-exhaustion observations. No partial manifest or index entry may appear as a consumable snapshot; staged debris is diagnostic/unpublished, not proof.

Pure reachability computes the closure of every pin. GC plans are sorted, bounded, scratch-only and require a stable root generation plus exclusive publication/collection coordination. If pin generation changes, a root is missing, traversal fails, a cycle occurs or ownership is uncertain, abort deletion and retain bytes. Do not call the baseline flat keep-list GC on a shared DAG. Exercise interrupted compaction/publication and a reader/publisher pin race: either the prior complete closure or the new complete closure remains reachable, never a dangling live reference. GC may reclaim only proven unreachable experimental objects after complete replacement publication. Measure temporary peak bytes and compaction cost; this does not assert power-loss durability, availability or storage trust.

### 6. Separate pure evidence decisions from effects

Pure Rust core logic owns profile/reference validation, canonical graph/page planning, completeness/equivalence comparisons over supplied facts, reachability/GC plans, accounting and decision derivation. It must return identical plans/typed failures for identical supplied facts, independent of filesystem order or host clocks. The thin Rust effect shell owns KVM capture/restore, filesystem staging/publication/locks, object reads/hashes, clock/resource observations and collection execution. Nickel owns human-authored protocol and reviewable receipt contracts; Rust emits runtime snapshot/measurement records. No external runtime, containers or hosted services are required.

### 7. Retain raw costs before making a decision

Each row binds source revisions (including experiment), exact commands/toolchain/build identities, kernel/initrd/workload hashes, host/KVM/progress profile, topology, config and Nickel protocol digests, seed, cohort/root/reference/object IDs, codec/schema/compression settings, chain depth and keyframe interval. Bind paired full-state/continuation evidence and operation status to raw observation artifacts by exact hash and length.

Record logical bytes represented; Arc shared-base/overlay bytes separately; unique decoded page bytes and object counts; compressed payload bytes; manifest/index/non-memory bytes; total retained and peak staging bytes; explicit dedup numerator/denominator and whether zero pages are elided; hashing/compression/serialization CPU costs, bytes read/written and peak memory; capture, publish, materialize, restore, seek and bounded continuation wall durations per repetition. Record cache state, warm/cold procedure and confounders; if controlled cold-cache conditions cannot be established, report that limit rather than labeling them cold. Preserve every raw row, failures and exclusions; derive distributions and ratios reproducibly without cherry-picking or double-counting shared objects. Host durations are observations, not guest scheduling input or deterministic latency promises.

Before runs, owners freeze each required cohort, mandatory correctness/safety checks, resource ceilings, and the measured trade-off criteria with units/direction and owner rationale. No numeric speedup threshold is invented here. Missing criteria block execution/adopt; no post-hoc favorable threshold changes. `adopt` requires all mandatory cohorts admitted, fidelity/safety checks passing, complete repeatable measurements within the declared bounds and the predeclared trade-offs satisfied. It only recommends a separate reviewed production migration. `defer` records unavailable/invalid baselines, missing KVM/cohorts, incomplete observations or unresolved trade-offs with exact blockers; `reject` records a validly evaluated failure of the mandatory criteria. Both are complete outcomes if the receipt is reproducible. Criteria changes create a new profile/receipt rather than rewriting the old result.

## Ownership, Adoption and Boundaries

VMM snapshot maintainers review state fidelity; explorer/replay-evidence maintainers maintain the protocol/harness and decision receipt, with a named responsible maintainer recorded before execution. Adoption first passes this evaluation's fidelity, negative-path and bounded-measurement gates, then a distinct production migration proposal must review codecs/public references, all consumers, retention compatibility and rollback/removal. No implementation, measurement or adoption is claimed now. A valid receipt never promotes replay proof by itself.

`repair-incremental-snapshot-lineage` remains the sole repair owner. `externalize-large-dogfood-artifacts` retains adapter selection/materialization and tracked-payload deletion authority. `causality-analysis-engine` and `extract-failure-reducer-core` retain attribution and reduction. Sibling debugger/witness/PMU changes are optional future consumers, not dependencies. Current explorer branching and retained parents provide the use case without them.

## Risks and Evidence Limits

Hashing, small-object overhead, indexes, non-memory payloads, chain traversal and GC staging may outweigh deduplication; dense writes may lose compression or increase latency. Baseline lineage defects may prevent any valid deep comparison. Limited local host/cache conditions constrain generalization. A defer/reject recommendation is preferable to a favorable result derived from invalid state. This delivery contains source review and structural planning only: no fixtures, benchmarks, KVM continuation, durability, proof promotion, release approval, sync or archive evidence.
