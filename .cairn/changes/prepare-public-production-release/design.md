# Release preparation design

## Decision

Reuse Cairn policy selection, the portable completion registry, replay-readiness and the seven-row KVM matrix. Public source availability and production fitness are separate decisions. A passing static check cannot substitute for admitted current-source replay evidence.

## Lifecycle repairs

Synchronize reviewed delta requirements through Cairn, preserving incomplete tasks and active changes. Requirement synchronization admits obligations; it is not proof of their implementation. Fix missing task references using the requirement actually governing validation. Never delete markers merely to clear coverage.

## Public boundary

README points to supported Rust-only local-machine workflows, licensing and existing security guidance when present. Date exact verification outcomes and identify external prerequisites. Historical receipts retain their original source and verdict. Do not turn historical test counts into live inventory.

## Verification

Run existing native validation/coverage and the pinned portable baseline before source changes. Run relevant existing gates after repairs. Use pueue for long builds and KVM commands. Retain local raw output separately from a concise tracked receipt. A clean candidate and genuine producer results remain prerequisites for final production promotion; a dirty preparation tree is not a release-tested revision.
