## Decision

Add RunningSumBy alongside unchanged RunningSum. Share numeric accumulation in a private sum_rows helper with borrowed SumSelection { field, value_field, key_field: Option<&str> }. Unkeyed uses None and one group; keyed uses existing RunningCountBy's in-place grouping pattern. Evaluate/admit/charge all child rows, canonical sort then source-position deduplicate with first-projection priority before grouping. Key lookup uses canonical kind/text/process/source_kind precedence, otherwise derived strings. Exact string equality; missing is not an empty key. No normalization/coercion.

For keyed rows, sort unique rows by key then canonical order, skipping if ordered. Resolve each group's end and key presence before mutating output, preserving original membership under output/key/value aliases. For every unique row, evaluate predicate against original values; parse a complete finite numeric operand only when matching, including on missing-key rows so keys cannot suppress invalid measurements. Present-key groups accumulate ordinary binary64 in canonical order, starting at +0.0. Validate every intermediate total immediately; overflowing groups fail InvalidNumber even if later values could cancel. Missing-key groups do not accumulate or annotate; remove stale output after predicate/operand validation. Nonmatching rows retain their group's current total; invalid nonmatching operands are not read. Reuse destination strings and existing JSON number formatting. Admit generated envelopes immediately and restore canonical output order. No key map, copied key strings, prefix copies or second event collection. Canonical stable sorting preserves duplicate priority; post-dedup key/final sorts can be unstable.

Validate all three names, predicate and input on empty sources. Preserve normal child work plus every materialized row before dedup and visited predicate child charges, shared structural/scan/derived/result/prefix bounds, moments and full query/key/value/predicate/source/result receipt binding. New readers required; existing schema and valid legacy semantics remain unchanged. Keys are caller-selected grouping, not proof of VM/history coherence.
